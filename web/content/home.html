What is C--?

C-- (pronounced “C minus minus”) is a statically typed, imperative systems programming language built as a compiler design project. Its guiding principle is Safety by Removal: instead of adding a garbage collector, a borrow checker, or runtime sanitizers on top of C, C-- deletes the features that make memory corruption possible. There are no raw pointers, no null values, no pointer arithmetic and no uninitialized variables, so the bugs that depend on them cannot be written.

The toolchain is written in pure Python with zero external runtime dependencies. A handwritten lexer, a recursive descent parser with Pratt precedence climbing, and a semantic analyzer check every program before it runs. Verified programs then execute in a deterministic tree-walking interpreter, or are transpiled into self-contained, bounds-checked ISO C99 that compiles cleanly with GCC, Clang, or MSVC.

Not to be confused with the older C-- intermediate language used inside the Glasgow Haskell Compiler. This C-- is a source language for people writing programs.

Why memory safety matters

Microsoft’s Security Response Center has reported that about 70% of the vulnerabilities it assigns a CVE each year are memory-safety issues, and the Chromium project reports a similar share among its serious security bugs (MSRC, 2019; Chromium Security). Buffer overflows, use-after-free, and null dereferences are the usual culprits. C-- removes the language features those bugs rely on, while keeping the explicit, predictable style that makes C easy to reason about.

01

Eliminated hazards

Rather than detecting unsafe operations after the fact, C-- removes the underlying constructs outright:

Raw pointers
No address-of (&), dereference (*), or pointer arithmetic exists in the grammar.
Null references
Absent by construction. Every binding requires a statically verified initial value.
Unchecked indexing
All collection accesses validate bounds at runtime with deterministic traps.
Implicit coercions
Strict static typing prevents silent narrowing, signed/unsigned mismatches, and truthy casts.
02

Design philosophy

Modern memory-safe languages typically trade simplicity for expressive alias tracking (borrow checking, lifetime annotations) or a garbage-collected runtime.

Where verification of arbitrary aliasing is complex, C-- enforces deep-copy value semantics and lexical immutability by default.

By treating composite collections (array, list, stack, queue) as isolated values on assignment and argument passing, C-- guarantees alias freedom without lifetime annotations.

Language features at a glance

  • Static types: 64-bit int, IEEE-754 float, strict bool, and UTF-8 string.
  • Built-in containers: array<T>, list<T>, stack<T>, and queue<T> with value semantics.
  • Structured control flow: if/else, switch, while, do-while, and for, with mandatory braces.
  • Typed functions: explicit parameter and return types, recursion with a call-depth guard.
  • Friendly diagnostics: 60 error codes with plain-language explanations, fixes, and “did you mean” suggestions.
  • Two backends: a reference interpreter with a step watchdog, and an ISO C99 transpiler.

Get started in a minute

C-- needs only Python 3.10 or newer. Clone the repository and run a program directly:

git clone https://github.com/ronitmexson2924/C--.git
cd C--
python3 -m cmm run demo.cmm        # run in the interpreter
python3 -m cmm check demo.cmm      # type-check only

Prefer not to install anything? Use the online C-- playground, browse the syntax reference, see how the compiler pipeline works, explore the language architecture, or meet the team behind C--. The full source is on the C-- GitHub repository.
