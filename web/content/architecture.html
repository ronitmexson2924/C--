Core guarantees

C-- language architecture and safety guarantees

Six invariants that the C-- compiler enforces across the lexical, syntactic, semantic, and code generation phases. Together they make C-- programs memory safe without a garbage collector or a borrow checker. Each card links to a runnable example.

01 CWE-119 · CWE-416 · CWE-476

Spatial & temporal memory safety

Buffer overflows, null dereferences, and use-after-free are structurally unrepresentable. Allocation and reclamation for dynamic structures are managed by the runtime and emitted C99 helpers.

02 Alias freedom

Deep-copy value semantics

Containers behave like scalars. Binding a collection to a new name or passing it to a function performs a deep clone, preventing unintended mutation across call frames.

03 Binding discipline

Immutability by default

let bindings are immutable for their whole lexical scope. Reassignment is permitted only on bindings marked mut, and uninitialized declarations are rejected at parse time.

04 Error recovery

Precision diagnostics

60 structured diagnostic codes render source context, column-accurate carets, root-cause explanations, remediation hints, and edit-distance identifier suggestions.

05 Execution targets

Dual-backend compilation

Execute in the deterministic tree-walking reference interpreter (with step and call-depth guards), or transpile into self-contained, bounds-checked ISO C99.

06 First-class containers

Intrinsic abstract data types

Fixed-length array<T>, resizable list<T>, LIFO stack<T>, and FIFO queue<T> are generic types checked by the semantic analyzer.
