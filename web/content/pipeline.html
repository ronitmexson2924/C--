Internal architecture

The C-- compiler pipeline: lexer, parser, analyzer, and backends

Four stages translate UTF-8 source into verified AST nodes, direct evaluation, or portable ISO C99. Each stage can be inspected against the code currently in the playground.

  1. Stage 01 cmm/lexer.py

    Lexical scanner

    Normalizes UTF-8 input and scans it into a deterministic stream of typed tokens with exact 1-indexed line and column spans.

    Output → List[Token]
  2. Stage 02 cmm/parser.py

    Recursive descent parser

    Builds an Abstract Syntax Tree using LL(k) statement parsing combined with 10-tier Pratt precedence climbing for expressions.

    Output → Program(AST)
  3. Stage 03 cmm/analyzer.py

    Semantic analyzer

    Resolves lexical scopes, checks type compatibility, enforces let/mut rules, and verifies return completeness.

    Output → Verified AST
  4. Stage 04 interpreter · codegen

    Dual execution backends

    Target A — tree-walking reference evaluator.
    Target B — hardened ISO C99 code generator.

    Output → stdout · C99

Normative reference interpreter

cmm/interpreter.py executes verified AST nodes with deterministic activation records, deep-copy value semantics, checked arithmetic, and a 100,000-step watchdog that stops runaway loops in interactive sessions.

ISO C99 source-to-source transpiler

cmm/codegen_c.py lowers C-- into portable C99 for gcc -std=c99 -O2 or clang, injecting runtime bounds assertions, division-by-zero traps, and deep-copy helpers.
