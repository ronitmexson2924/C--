Abstract

A loop containing an if/else cannot be executed by SIMD hardware as written: a conditional jump steers one instruction pointer, while a 512-bit vector processes sixteen elements that may each need a different path. This case study shows how AVX-512 replaces the jump with a per-lane predicate held in a mask register (k1–k7), so both branches become a single straight-line instruction stream, and measures what that is worth.

The solution is innovative in method: every claim is established three independent ways. (1) A C-- “SIMD lab”, written in our own memory-safe language, models zmm registers and mask registers as safe values, executes the loop four ways, proves they agree lane by lane, simulates two branch predictors and estimates instruction counts and cycles. (2) GCC 13’s actual output shows how a production compiler applies masking, and when it refuses to. (3) A hardware benchmark on an Intel Xeon (Cascade Lake) times six implementations on five data distributions and directly captures the AVX-512 frequency penalty.

Masking cuts dynamic instructions by 18–21× and branches by 32×, removes every data-dependent misprediction, and makes run time independent of the data: about 19× faster than the branchy scalar loop on random data and 3.4× on predictable data. The results also show that, on this CPU, 256-bit masking beats 512-bit masking because the square-root unit is the bottleneck and 512-bit instructions lower the core clock.

1. Problem statement

A data-analysis kernel contains conditional control flow inside a loop (the kernel on the cover page). The case study asks us to:

  1. Explain why traditional branching instructions (CMP + JMP) break SIMD pipelining and prevent vectorization.
  2. Demonstrate how the compiler uses masked vector operations (AVX-512 mask registers k1–k7, or SIMD blend instructions) to vectorize the loop without explicit branching.
  3. Evaluate the instruction count and performance impact when branch misprediction penalties are eliminated via vector predication.

We were asked to solve the problem in an innovative way. We do this by using the C-- language we built, and by checking the model against the real compiler and real hardware.

2.1 Why C--?

C-- (C Minus Minus) is a statically typed, memory-safe imperative language with no pointers, no null, immutable-by-default bindings and bounds-checked collections. Because C-- has no pointers or inline assembly, a vector register has to be modelled as a value, array<float>(16), and a mask register as array<bool>(16). Each AVX-512 instruction becomes a small pure function (vcmp_gt_zero, vsqrt_maskz, vload_maskz, vstore_mask), so the lane-level semantics of predication can be read, executed and tested directly.

The language's safety rules also demonstrate one of masking's key benefits. When the tail mask k2 is deliberately removed from the load, C-- does not silently read past the array as C would. It stops with runtime error: index out of range (index 100, length 100) (error R006). The very fault that AVX-512 masked loads exist to prevent becomes visible.

3. Question 1 — Why CMP + JMP breaks SIMD

At -O2, GCC compiles the loop into the following hot loop. The branch to .L11 depends on the data in every iteration:

.L5:  movss   (%rdi,%rax), %xmm0     ; load A[i]
      comiss  %xmm1, %xmm0           ; CMP  A[i] with 0.0
      jbe     .L11                   ; JMP  if A[i] <= 0     <-- data-dependent branch
      sqrtss  %xmm0, %xmm0           ; then-path
      movss   %xmm0, (%rsi,%rax)
      addq    $4, %rax
      cmpq    %rax, %rcx
      jne     .L5
.L11: pxor    %xmm0, %xmm0           ; else-path: B[i] = 0
      movss   %xmm0, (%rsi,%rax)
      ...
Answer to Question 1
  1. One program counter, many lanes. A SIMD instruction applies one operation to 16 lanes at once, but a jump moves the single instruction pointer. When lanes disagree (some A[i] > 0, some not), no jump target is right for all of them: the branch is divergent. Vectorization requires the compiler to remove the control flow first (if-conversion), turning the branch into data: a per-lane predicate.
  2. The branch serializes the pipeline. The CPU must predict jbe before comiss completes. On random data it guesses wrong about half the time, and each wrong guess flushes the speculatively executed work and restarts fetch. We measured about 19–23 TSC ticks per misprediction (≈ 20 core cycles, §5.3), several times the cost of the useful work per element.
  3. Hidden side effects block if-conversion. If-conversion computes sqrtf on lanes the program never asked for, which is only legal when that has no visible effect. sqrtf of a negative number may set errno, so GCC refuses to vectorize until -fno-math-errno is given (Table 2). Floating-point exception flags and out-of-bounds accesses in the final partial vector are the other side effects that predication must suppress.

4. Question 2 — Masked vector operations

4.1 What the compiler emits

With -O3 -mavx512f -mprefer-vector-width=512 -fno-math-errno, GCC if-converts the loop and predicates it with mask register k1:

.L4:  vcmpps   $1, (%rdi,%rax), %zmm1, %k1   ; k1[l] = (0.0 < A[i+l])  for 16 lanes
      vsqrtps  (%rdi,%rax), %zmm0{%k1}{z}    ; sqrt where k1 = 1, 0.0 where k1 = 0
      vmovups  %zmm0, (%rcx,%rax)            ; store 16 results
      addq     $64, %rax
      cmpq     %rax, %rsi
      jne      .L4                            ; only branch left: loop-back, always predictable
Answer to Question 2
  • vcmpps … %k1 evaluates the if condition for all 16 lanes and stores it as 16 bits in mask register k1. The CMP survives as data; the JMP is gone.
  • {%k1}: the square root only takes effect in lanes whose mask bit is 1. Masked-off lanes raise no floating-point exceptions, because AVX-512 suppresses faults on inactive lanes.
  • {z} (zero-masking) writes 0.0 into inactive lanes. That is the else branch, executed by the same instruction at no extra cost. Merge-masking (without {z}) would keep the destination's previous value instead.
  • Both branches collapse into one instruction stream, and the loads fold into the memory operands of vcmpps and vsqrtps.
  • A second mask k2 handles the final partial vector, so no scalar clean-up loop is needed and memory past the array is never touched (our intrinsics version, Appendix C).

Read as integers (kmovw): k2 = 15 (0b1111) and k1 = 2 (0b0010). The program checks that the masked result equals the scalar branch for every element of every dataset.

The heart of the C-- model is just two instruction functions:

// vcmpps k1{k2}, zmm1, zmm0, _CMP_GT_OQ   (zmm0 = 0.0; result ANDed with k2)
fn vcmp_gt_zero(v: array<float>, k: array<bool>) -> array<bool> {
    mut m = array<bool>(lanes512(), false);
    for (mut l = 0; l < lanes512(); l = l + 1) { m[l] = k[l] && v[l] > 0.0; }
    return m;
}

// vsqrtps zmm2{k1}{z}, zmm1   (zero-masking IS the else-branch: inactive lanes become 0.0)
fn vsqrt_maskz(v: array<float>, k: array<bool>) -> array<float> {
    mut r = array<float>(lanes512(), 0.0);
    for (mut l = 0; l < lanes512(); l = l + 1) { if (k[l]) { r[l] = sqrt_nr(v[l]); } }
    return r;
}

4.3 Without mask registers: compare + blend (AVX2)

Without k registers the predicate is a vector of all-ones/all-zeros lanes. The square root runs on every lane (negative lanes produce NaN and set the invalid flag), and a blend selects the result. Because the else value is 0.0, GCC uses a bitwise vandps, which is cheaper than vblendvps:

.L4:  vsqrtps   (%rdi,%rax), %ymm1          ; sqrt of all 8 lanes, including negatives -> NaN
      vcmpltps  (%rdi,%rax), %ymm2, %ymm0   ; ymm0 = all-ones where 0 < A
      vandps    %ymm1, %ymm0, %ymm0         ; blend: keep sqrt where all-ones, else 0.0
      vmovups   %ymm0, (%rcx,%rax)

Without masks the remaining N mod 8 elements need a separate scalar loop, which still contains the branch.

4.4 Innovation: algebraic predication

Because sqrt(0) = 0, the whole if is equivalent to B[i] = sqrt(max(A[i], +0.0)). vmaxps returns its second operand when either input is NaN or both are zero, so max(A, +0.0) maps negatives, −0.0 and NaN to +0.0: exactly the else-branch, bit for bit. We verified this on 0, −0, ±NaN, ±∞ and denormals. The condition disappears into arithmetic; only the tail mask k2 remains.

  • Branches drop 32× (2.0 → 0.0625 per element). The one that remains is the loop-back branch, which mispredicts once, at loop exit.
  • Data-dependent branches drop from one per element to zero, so speed no longer depends on the data.
  • The C-- lab reaches the same result for N = 100: 800 → 46 instructions and 200 → 7 branches.

5.3 The cost of branch mispredictions

  • The scalar loop's time varies by up to about 6× (2.3 → 13.7 ticks) depending only on the signs of the data. Every vector version takes the same time on every dataset.
  • Penalty per misprediction. With random signs about half of the branches mispredict, since no predictor can learn random data. The alternating dataset does the same amount of work (half the elements need a square root) but is perfectly predictable. Hence (13.7 − 2.3) / 0.5 ≈ 23 TSC ticks per misprediction; the 90% dataset gives ≈ 19. That is about 7–8 ns, or roughly 20 core cycles.
  • 83% of the scalar loop's time on random data is misprediction recovery: (13.7 − 2.3) / 13.7.

5.5 The new bottleneck, and a surprise

Once the branches are gone, the limit is the square-root unit, not the number of instructions. Using published reciprocal-throughput figures for Skylake-SP / Cascade Lake, each measurement implies a core clock, and the results are consistent with each other:

Table 7. Square-root throughput and implied core clock
KernelSquare-root throughput (published)Measured (ticks / element)Implied core clock
Scalar sqrtss3 cycles / element2.4713.4 GHz
256-bit vsqrtps ymm6 cycles / 8 lanes0.6183.4 GHz
512-bit vsqrtps zmm12 cycles / 16 lanes0.7252.9 GHz

On this microarchitecture a 512-bit square root has the same per-element throughput as a 256-bit one (0.75 cycles per element), so 512-bit vectors cannot be faster here, and heavy 512-bit floating-point instructions also move the core to a lower frequency “license”. We captured this directly by timing the same 256-bit masked kernel before and after a 30 ms burst of 512-bit vsqrtps:

Answer to Question 3

Vector predication reduces the dynamic instruction count from 8 to 0.375–0.44 per element (≈ 18–21×) and the branch count from 2 to 0.0625 per element (32×), and it eliminates all data-dependent mispredictions. Each misprediction costs about 20 core cycles, and on random data they consume 83% of the scalar loop's time. Removing them gives a measured ≈ 19× speedup on random data and 3.4× on perfectly predictable data. Above all, run time becomes independent of the data: 0.725 ticks per element on every dataset.

6. Conclusions and recommendations

  1. Branches are the obstacle, not the condition. A CMP + JMP gives all lanes one control flow and makes throughput depend on the predictor. Turning the condition into a per-lane predicate keeps the computation and removes the control flow.
  2. AVX-512 masks make predication complete. vcmpps → k1 followed by vsqrtps{k1}{z} executes both branches in one instruction: zero-masking supplies the else, masked lanes raise no exceptions, and a tail mask k2 replaces the scalar epilogue without touching memory past the array.
  3. The payoff is ≈ 18–21× fewer instructions, 32× fewer branches, zero data-dependent mispredictions, and 3.4–19× measured speedups with data-independent run time.
  4. Choose the vector width per CPU. On Cascade Lake the square-root unit, not the instruction count, is the limit, and 512-bit instructions lower the clock. AVX-512VL masking at 256 bits is the fastest choice here. On CPUs without this frequency penalty (Ice Lake and later, AMD Zen 4) 512-bit masking is expected to win.
  5. Look for algebraic predication. When the else value equals the function at a boundary (here sqrt(0) = 0), sqrt(max(A, 0)) removes the condition altogether.
  6. Compiler flags decide legality. Without -fno-math-errno, errno semantics prevent GCC from vectorizing at all.
  7. Safe languages make SIMD semantics testable. Modelling registers as values in C-- exposed the lane semantics, proved the four strategies equivalent, and turned the out-of-bounds tail access that k2 prevents into a reported runtime error.
